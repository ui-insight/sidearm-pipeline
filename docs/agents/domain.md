# Domain docs

This is a single-context repository.

## Before exploring

- Read the root `CONTEXT.md` for the project's domain language.
- Read ADRs in `docs/adr/` that touch the area being changed.
- If either source is absent, proceed without proposing that it be created
  preemptively.

## Vocabulary

Use the glossary's terms in issue titles, implementation proposals, tests, and
documentation. Avoid synonyms that `CONTEXT.md` explicitly rejects. If a needed
concept is missing, note the vocabulary gap for a future domain-design session.

## Architecture decisions

Surface conflicts with an existing ADR explicitly rather than silently
overriding the recorded decision.
